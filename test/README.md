# Регрессионный прогон

Гоняет приложение в headless Chrome через CDP. Зависимостей нет — нужен только
Node 22+ (встроенный `WebSocket`) и установленный Google Chrome.

```bash
docker compose up -d --build          # или ./start.command
node test/smoke.js                    # по умолчанию http://127.0.0.1:8081/
APP_URL=https://graph.heeprod.ru/ node test/smoke.js
```

Что проверяется:

- приложение грузится, `boot()` отрабатывает, в консоли нет исключений;
- демо-сид разбирается, проект создаётся из шаблона;
- `validateProject()` не находит претензий, метрики графа считаются;
- отрисовываются все типы страниц: дашборд, холст, таблица, канбан;
- узел **реально перетаскивается мышью**, позиция пишется в `n.p[pageId]`;
- позиция переживает перезагрузку (IndexedDB);
- **экспорт → импорт** сохраняет позиции узлов, камеру страницы и колонки холста;
- `viewer.html` собирается, несёт позиции и включает режим только-чтения;
- service worker регистрируется.

Скрипт выходит с кодом 1, если хоть одна проверка провалилась.

## Грабли

- При первом запуске поверх всего открывается справка (`#modal.open`) и перехватывает
  клики — тест закрывает её перед drag'ом.
- `dl()` объявлен как `const`, подменить через `window.dl` нельзя: выгрузки
  перехватываются на уровне `URL.createObjectURL`.
- Узлы холста — это `.nd[data-n]`, а обработчик мыши висит на контейнере `#cv`.
- **Ждать надо `UI.booted`.** `boot()` в самом конце САМ открывает нужный экран,
  уже после того, как появились база и `P`. Ждать этих признаков — значит начать
  работу до того, как boot покажет главную поверх редактора.
- **Дождаться `P` — мало.** `createFromTemplate()` асинхронна, и данные появляются
  РАНЬШЕ, чем закрывается главный экран: в это окно `#home` лежит поверх редактора,
  `elementFromPoint` попадает в него, клики и сочетания клавиш уходят не туда.
  Симптом — плавающее «не нашёл узел на холсте» с цепочкой `DIV#home.open`.
  Ждать надо признак «редактор виден»: `!document.body.classList.contains('onhome')`
  (константа `EDITOR_SHOWN` в наборах).
- **`Too Many Requests` в наборах, которые входят в аккаунт** (`cloud`, `live`, `api-flow`)
  — это не поломка продукта, а ограничитель входа: `/api/auth/login` пускает 10 попыток
  за 5 минут с адреса, и несколько прогонов подряд его выбирают. Счётчик живёт в памяти
  контейнера `api`, поэтому `docker compose up --build` его НЕ сбрасывает, если менялся
  только клиентский код и контейнер не пересоздавался. Лечится `docker compose restart api`
  или паузой в пять минут.

## Совместимость со старыми файлами

```bash
node test/legacy.js                    # по умолчанию http://127.0.0.1:8081/
APP_URL=https://graph.heeprod.ru/ node test/legacy.js
```

Отдельный набор: проверяет, что приложение открывает всё, что умело открывать раньше —
экспорт Graph Studio 1.1/1.2 (камера в `page.view`, позиции в `n.p`, области, стикеры, вехи,
свои поля), старый экспорт с легаси-позициями `n.x/n.y/pinned`, формат Roadmap Studio
(через `isLegacy()`/`fromLegacy()`), файл из одних узлов и связей, бэкап-бандл версии 1.
Плюс round-trip: старый файл → экспорт → импорт без потерь.

Набор ничего не пишет на сервер — только локальное состояние браузера в одноразовом профиле,
поэтому его безопасно гонять и против боевого адреса.

## Конструктор KYC Flow

```bash
node test/flow-rules.js                # правила, без браузера и сервера
node test/flow.js                      # страница в браузере, против собранного контейнера
```

`flow-rules.js` гоняет чистые модули (`src/flow/rules.js`, `model.js`) на node: матрицу
совместимости сокетов, применимость профилей, контрольные числа seed, контракт `kycflow/1`
по `docs/kycflow.schema.json`, валидатор и байтовое совпадение серверной копии правил.

`flow.js` — сценарии ТЗ мышью и клавиатурой: грамматика, библиотека, С11 «с нуля», профили
и оверлеи, шаблон, выгрузки (xlsx разбирается exceljs, архив — fflate), валидатор.
**Единственный набор, которому нужен `node_modules`** — ради этих двух парсеров: в CI перед
ним стоит `npm ci --omit=dev`, `scripts/verify.sh` ставит зависимости сам, если их нет.
Состояние конструктора читается через `FLOW.state()` и `FLOW.call()` — крючки модуля,
которые ходят теми же путями, что и человек.

- **Просмотрщик офлайн проверяется только против сборки**: dev-сервер Vite на запрос
  `viewer-template.html` отдаёт `index.html`, и тест это распознаёт.
- **Проверка просмотрщика уводит вкладку на `file://`** — следующий блок открывает
  доску заново по сохранённому `P.id`.
- С8 (`flow_profile`) — в `test/mcp.js`, С9 (двое на одной схеме) — в `test/live.js`,
  касание — в `test/touch.js`.

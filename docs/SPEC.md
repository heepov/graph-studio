## Changelog 1.2 (29.07.2026) — PWA + File System Access

Инструмент теперь можно **установить как приложение** (собственное окно, иконка в доке, оффлайн) и хранить проекты в **реальных файлах на диске**. Веб-технологии те же; изменилась доставка и хранение.

- **Запуск по http, не file://.** PWA и FSA требуют secure context. Локально — `start.command` (двойной клик: поднимает `python3 -m http.server 8123` и открывает `http://localhost:8123/graph_studio.html`) или любой статический хостинг (GitHub Pages и т.п.). Файл перестал быть строго «одним файлом»: приложение = `graph_studio.html` + `manifest.webmanifest` + `sw.js` + `icon.svg`.
- **PWA-оболочка.** `manifest.webmanifest` (standalone, иконки-SVG), `sw.js` (network-first кэш app-shell → оффлайн-запуск), регистрация SW и `beforeinstallprompt` в блоке перед `boot()`. Кнопки «Установить приложение» (стартовый экран `#pInstall` + сайдбар `#navInstall`), появляются по `beforeinstallprompt`.
- **File System Access (прогрессивное улучшение).** Блок «FILE SYSTEM ACCESS». Проект можно связать с настоящим `.json`: «Открыть файл…», «Связать с файлом…», «Сохранить как…», «Отвязать» (в «Экспорт и импорт» → «Файл на диске»). Правки **автосейвятся в файл** (`scheduleFileSave`, дебаунс 1.2 с, дергается из `save()`). Хэндлы файлов лежат в meta store под `fh:<projectId>` (FileSystemFileHandle структурно клонируется в IndexedDB), права перезапрашиваются по жесту. `UI.fileName` показывается в статусе (📄). Значок 📄 на карточках проектов, привязанных к файлу. IndexedDB остаётся автосейв-кэшем.
- **Папка хранилища (vault, как у Obsidian).** `showDirectoryPicker` → хэндл папки в meta `vault`, список её проектов — в meta `vaultIds`. `loadVault(dir)` сканит папку, читает каждый `.json` (legacy → `fromLegacy`), кладёт в кэш `projects`, привязывает файловый хэндл, удаляет из кэша пропавшие. Новый проект пишется файлом в папку сразу (`vaultAddProject`, дергается при создании из шаблона). Смена папки (`chooseVault`) пересканирует и подтягивает файлы новой папки, убирая проекты старой из кэша. «Обновить из папки» (`refreshVault`), «Отключить» (`disconnectVault`). На boot — авто-подтяжка, если доступ к папке уже выдан (`queryPermission==='granted'`, без запроса). IndexedDB становится кэшем папки; id проектов из `.json` стабильны (у файлов без нативного id — `vf_<имяФайла>`). Кнопка `#pVault` + строка `#vaultStatus` на стартовом экране. Только Chrome/Edge (secure context); без FSA — кнопка скрыта.
- **Записи в файл сериализованы** (`_writeLock`) — одновременные `createWritable` по одному файлу иначе конфликтуют и могут обнулить файл.
- **Откат без FSA** (file://, Safari, Firefox): `openProjectFile`→`importJson`, `saveProjectToFile`→скачивание. Ничего не ломается.
- **Фасетный фильтр** (`facetCounts` + `buildFilterMenu`): у каждого значения фильтра — число подходящих узлов текущей страницы (`pageNodes(pg)`); пустые для страницы значения скрыты, переключатель «Показать все значения» (`UI.filterShowAll`) их раскрывает. Убирает путаницу «почему на доске X видна доска/категория Y» — модель пула не меняется, только релевантность списка.
- **Инлайн-создание из инспектора.** В селектах правки узла добавлен пункт «＋ Новый…»: тип/статус/категория (`createSchemaItem`), колонка холста (`createLane` — добавляет подпись колонки и закрепляет узел), значение своего select-поля (`createFieldOption`). Ключ генерится из названия (`schemaKey`), цвет статуса/категории берётся из `SCHEMA_PALETTE` (`nextColor`, первый неиспользованный). Полное оформление (цвет/форма/переименование/удаление) — по-прежнему в «Схеме проекта».

⚠️ **Грабли, стоившие отладки:** `const FSA` изначально был объявлен в блоке FSA (ниже по файлу), а верхнеуровневая привязка кнопки `#pOpenFile` ссылалась на него выше → **TDZ ReferenceError** валил весь скрипт до `boot()`, приложение не стартовало (на всех origin). Урок: любые `const/let`, на которые ссылается верхнеуровневый код, объявлять **до** первого использования (сейчас `FSA` объявлена рядом с `VIEWER`).

## 1. Что это

**Graph Studio** — редактор графов зависимостей: роадмапы, карты разблокировок («что чем заблокировано»),
процессы и любые схемы, где важны узлы, связи между ними и производные метрики (вес узла, критический путь, слои).

Одностраничное приложение в **одном самодостаточном HTML-файле**. Никакого бэкенда, сборки, npm, сети.
Открывается двойным кликом из файловой системы (`file://`), работает офлайн.

### Кто пользователь
Product manager, который держит в голове зависимости между продуктами и этапами и должен уметь:

- быстро ответить «что нас держит» и «что откроется, если закрыть X»;
- показать карту на совете директоров без подготовки слайдов;
- править данные там же, где смотрит, а не в отдельной таблице;
- завести вторую-третью тему (не только текущий роадмап) в том же инструменте.

### Ключевые продуктовые решения (не менять без веской причины)
1. **Колонка на холсте = глубина зависимости, а не календарь.** Это принципиально отличает инструмент
   от диаграммы Ганта: он отвечает на вопрос «в каком порядке это физически может поехать».
2. **Вес узла** = размер транзитивного множества потомков. Это метрика приоритета: «закрыв это, разблокируешь N».
3. **Типы связей делятся на блокирующие и неблокирующие.** Только блокирующие влияют на слои, вес и критический путь.
4. **Один пул узлов, много представлений.** Страницы (холст/таблица/канбан/дашборд) — это фильтры + способ отрисовки,
   а не отдельные наборы данных.
5. **Схема настраивается пользователем**, а не захардкожена: типы узлов, статусы, категории, типы связей, свои поля.

## 3. Модель данных

Всё состояние проекта — один JSON-объект. Он же лежит в IndexedDB, он же выгружается в файл.

```jsonc
{
  "id": "demo",                   // уникальный ключ в IndexedDB
  "name": "Демо · запуск маркетплейса",
  "desc": "одна строка описания для карточки проекта",
  "created": "2026-07-28",
  "updated": "2026-07-28",        // проставляется автоматически при каждом save()
  "deleted": false,               // 1.1: корзина — true прячет проект из списка (P0-2)
  "deletedAt": "2026-07-29",      // 1.1: дата мягкого удаления

  "schema": {
    "nodeTypes": [                 // форма и смысл узла
      {"key": "stage", "name": "Этап / продукт", "shape": "rect"},
      {"key": "gate",  "name": "Гейт / блокировка", "shape": "pill"}
      // shape: rect | pill | diamond  (визуально: прямоугольник / скруглённый / фиолетовый акцент)
    ],
    "statuses": [
      {"key": "red", "name": "заблокировано", "color": "#b3261e"}
    ],
    "categories": [                // в исходной карте это «треки»
      {"key": "F", "name": "Фундамент и блокировки", "color": "#6b7280"}
    ],
    "linkTypes": [
      {"key": "hard", "name": "Жёсткая блокировка", "color": "#9aa1b2", "style": "solid",  "blocking": 1},
      {"key": "soft", "name": "Мягкая связь",       "color": "#c9a227", "style": "dashed", "blocking": 0}
      // style: solid | dashed | dotted
      // blocking: 1 → влияет на слои, вес, критический путь; 0 → только рисуется
    ],
    "fields": [                    // произвольные пользовательские поля узла
      {"key": "wave", "label": "Волна", "type": "select",
       "options": ["Wave 1", "Wave 2"], "card": 1}
      // type: text | longtext | select | number | date | checkbox | list
      // card: 1 → значение показывается бейджем на узле холста
    ]
  },

  "nodes": [
    {
      "id": "LIC",                 // уникальный, редактируемый; при смене переписываются links
      "name": "Лицензионная модель EF ↔ НВ",
      "sub": "рамка: как Easy работает от имени банка",   // одна строка под названием
      "type": "gate",              // → schema.nodeTypes[].key
      "status": "amber",           // → schema.statuses[].key
      "cat": "F",                  // → schema.categories[].key
      "body": "длинное описание, plain text, переносы сохраняются",
      "draft": 0,                  // 1 → бейдж «черновик» в карточке
      "lane": null,                // ручной номер колонки на холсте; null = авто по зависимостям
      "f": {"wave": "Wave 1", "gate": "текст"},          // значения пользовательских полей
      "checks": [                  // вехи / чеклист
        {"t": "Утвердить модель", "s": "red", "b": 1, "z": "комментарий"}
        // t — текст, s → statuses[].key, b — флаг «жёсткий блокер», z — комментарий
      ],
      "p": {"p_main": {"x": 456, "y": 712}},   // ПОЗИЦИИ ПО СТРАНИЦАМ, ключ = page.id
      "x": null, "y": null,        // legacy-fallback позиции (из старого импорта), обычно null
      "pinned": 0                  // legacy-флаг, актуальная «закреплённость» = наличие p[pageId]
    }
  ],

  "links": [
    {"id": "l1", "from": "LIC", "to": "D_RKO", "type": "hard", "label": ""}
  ],

  "frames": [                      // области и дорожки на холсте
    {"id": "f1", "name": "Область", "kind": "frame", "x": 0, "y": 0, "w": 460, "h": 320, "color": ""}
    // kind: frame | lane (lane рисуется пунктиром, как вертикальная полоса-этап)
  ],

  "notes": [                       // стикеры
    {"id": "t1", "text": "Заметка", "x": 0, "y": 0, "w": 200, "h": 96, "color": ""}
  ],

  "pages": [
    {
      "id": "p_main",
      "name": "Продуктовый план",
      "kind": "canvas",            // canvas | table | board | dash
      "filter": {
        "q": "",                   // поиск по всему тексту узла
        "cats": [], "statuses": [], "types": [],     // пустой массив = не фильтруем
        "f": {"board": ["Продуктовый план"]},        // фильтр по пользовательским полям
        "blockersOnly": 0
      },
      "canvas": {
        "layout": "auto",          // auto (слои по зависимостям) | free (руками)
        "lanes": ["блокировки", "этап 1", "этап 2"], // подписи колонок, индекс = номер колонки
        "intro": "<b>HTML</b> над холстом",
        "introOff": 0,             // пользователь скрыл пояснение
        "crit": 0,                 // показывать только критический путь
        "ready": 0                 // показывать только узлы без входящих связей
      },
      "view": {"x": 120, "y": 40, "k": 0.9},   // 1.1: сохранённая камера холста (P0-3), только для canvas
      "table": {"cols": ["name","cat","status","step","weight","checks"],
                "sort": "step", "dir": 1, "group": ""},
      "board": {"groupBy": "status"}   // status | cat | type | step | f.<key>
    }
  ]
}
```

### Инварианты модели
- `links[].from/to` обязаны указывать на существующие `nodes[].id`. Битые связи молча игнорируются
  при построении графа, но их надо чистить (см. бэклог P1-6 «валидатор»).
- Граф **обязан быть ациклическим по всем связям** (не только блокирующим). Проверка `hasCycle()`
  вызывается при каждом добавлении связи; при цикле операция откатывается.
- `node.p[pageId]` создаётся только для страниц типа `canvas`. При удалении страницы записи в `p`
  остаются мусором — безвредно, но см. P2-4.
- Ключи в `schema.*` уникальны внутри своего массива. Удаление ключа, который используется,
  не мигрирует данные: узлы сохранят старое значение и потеряют оформление (пользователя предупреждают).

## 4. Хранилище и жизненный цикл данных

**IndexedDB** база `graphstudio`, версия 1, три store:

| Store | keyPath | Что лежит | Статус |
|---|---|---|---|
| `projects` | `id` | целые проекты | используется |
| `meta` | `k` | `{k:'last', v:projectId}`, `{k:'seen', v:1}` | используется |
| `snaps` | `id` | `{id, proj, name, at, nodes, links, data}` — именованные снимки версий | **задействован в 1.1** (P0-1) |
| `meta` | `k` | +`{k:'theme', v:'dark'\|'light'}` в 1.1 | тема оформления |

- `save(immediate)` — дебаунс 420 мс, ставит `P.updated = today()`, пишет весь проект целиком.
  Полная перезапись каждый раз: при 104 узлах это ~200 КБ на запись, приемлемо; на 1000+ узлов надо думать.
- `snapshot()` — кладёт `JSON.stringify(P)` в `undoS`, глубина 60, дебаунс 650 мс
  (чтобы ввод текста не забивал стек). `snapNow()` — форсированный снимок перед дискретным действием.
- `undo()` / `redo()` — полная замена объекта `P`, затем `gInval()` + перерисовка.
- При старте: открыть БД → загрузить список проектов → открыть последний (`meta.last`), иначе первый
  живой; **если проектов нет — показать стартовый экран** (шаблоны, среди них демо-проект), ничего
  не создавая молча (изменено в 1.1; раньше на пустой базе автосоздавался проект из `#seed`). При первом
  запуске — справка. Демо-проект из `#seed` теперь доступно как шаблон `{id:'demo'}` в массиве `TPL`.

**Режим просмотра**: `window.VIEWER = true` (ставится в экспортированном `viewer.html`).
В этом режиме IndexedDB не трогается вообще, проект берётся прямо из `#seed`,
все элементы с классом `.noview` удаляются из DOM.

## 5. Ядро: граф и метрики

`G()` — единственная точка вычисления производных величин. Результат кэшируется в `_g`,
инвалидируется через `gInval()` **после любой правки узлов, связей или типов связей**.

Возвращает:

| Поле | Что |
|---|---|
| `kids[id]` | `[{id, lid, soft}]` — исходящие связи |
| `par[id]` | `[{id, lid, soft}]` — входящие связи |
| `hardPar[id]` | массив id только по блокирующим связям — вход для слоёв |
| `layer[id]` | глубина: `0`, если нет блокирующих входящих; иначе `max(layer(предков)) + 1` |
| `DESC[id]` / `ANC[id]` | `Set` транзитивных потомков / предков (по всем связям) |
| `W(id)` | **вес** = `DESC[id].size` |
| `crit` | `Set` критического пути |

**Критический путь** — цепочка от корня с максимальной суммой `DESC.size + 1` вдоль блокирующих связей.
Считается мемоизацией `f(id) = max(f(детей)) + DESC[id].size + 1`, стартовая точка — узел без входящих
с максимальным `f`.

`stepOf(n)` = `n.lane`, если задан вручную, иначе `layer[n.id]`.

⚠️ Защита от циклов в `layer()` — флаг `seen`, который при цикле вернёт `0`. То есть даже если цикл
как-то просочится, приложение не зависнет, но раскладка будет неверной.

## 6. Холст

### Система координат
- **Мир** — координаты узлов (`x`,`y` в пикселях при zoom = 1).
- **Камера** `view() = {x, y, k}`, своя на каждую страницу, живёт в `UI.view[pageId]` (в памяти, не сохраняется).
- Применяется одним трансформом на `#scene`: `translate(x,y) scale(k)`.
- `toWorld(clientX, clientY)` — обратное преобразование с учётом `getBoundingClientRect()` контейнера.
- `#edges` — SVG размером 1×1 с `overflow:visible`; так связи рисуются в мировых координатах,
  включая отрицательные, без гигантского холста.

### Константы
```
NW = 212, NH = 74          размер узла
COLGAP = 108               между колонками
SUBGAP = 34                между подколонками внутри колонки
ROWGAP = 12                между узлами по вертикали
PADX = 60, PADY = 70       отступы раскладки
GRID = 8                   шаг привязки при перетаскивании
zoom: 0.08 … 3             клампы масштаба
wheel-zoom factor: 0.82 … 1.22   (иначе трекпад/синтетические события дают скачок)
```

### Авто-раскладка `autoLayout(nodes)`
Пятиэтапный алгоритм (перенесён из исходной визуализации, менять осторожно):

1. **Колонка** каждого узла = глубина по блокирующим связям внутри видимого подграфа
   (`n.lane` перебивает расчёт). Пустые колонки схлопываются, но исходный номер сохраняется
   для подписи (`capIdx`).
2. **Локальный уровень внутри колонки** — зависимости между узлами одной колонки → подколонки.
3. **Первичная сортировка**: по весу убыв., затем по категории.
4. **6 итераций барицентра** — попеременно слева направо и справа налево, узел тянется к среднему
   индексу своих соседей. Это то, что распутывает стрелки.
5. **Позиционирование**: подколонки внутри колонки, вертикальное центрирование группы.

Возвращает `pos{id → {x,y}}` и `lanes[{x, idx, h}]` для подписей и пунктирных разделителей.

### Режимы раскладки страницы
- `layout: 'auto'` — позиции считаются каждый рендер; узел с `p[pageId]` берёт свою закреплённую позицию
  и получает бейдж 📌. Перетаскивание в этом режиме **закрепляет** узел.
- `layout: 'free'` — все позиции берутся из `p[pageId]`; при первом открытии страницы они засеиваются
  результатом авто-раскладки и сохраняются.

### Взаимодействия (`onDown` — единая точка входа)
Порядок проверок в `mousedown` важен, менять нельзя:

```
1. средняя кнопка / Space   → pan
2. .hit (толстая невидимая дорожка связи, 14px) → выбрать связь
3. .port                    → тянуть новую связь
4. .nd                      → выделение + drag узла (всех выделенных)
5. .fr .rs / .fr .fh        → resize / drag области
6. .stk .rs / .stk          → resize / drag заметки
7. пустое место             → рамка выделения (Shift — добавить к выделению)
```

Прочее:
- колесо — панорама; `Ctrl`/`Cmd` + колесо (и пинч на трекпаде) — зум к курсору;
- двойной клик по пустому — новый узел, по узлу — переименование на месте (`contenteditable`);
- правая кнопка — контекстное меню с подменю статусов и категорий;
- миникарта: клик и тяга перемещают камеру;
- при отпускании связи над узлом: `Shift` = второй тип связи из схемы.

## 7. Страницы

`renderPage()` — диспетчер: рисует панель страницы и вызывает `renderCanvas` / `renderTable` /
`renderBoard` / `renderDash`.

| Тип | Что умеет |
|---|---|
| **canvas** | всё из раздела 6; фильтры треков; переключатели «критический путь» и «доступное сейчас»; выбор типа связи по умолчанию; редактор подписей колонок |
| **table** | выбор колонок (ядро + любые пользовательские поля), сортировка кликом по заголовку, группировка по любому select-полю, правка в ячейках, мультивыделение с `Shift`/`Ctrl` |
| **board** | колонки по любому полю-списку (`status`, `cat`, `type`, `step`, `f.*`), перетаскивание карточки меняет значение поля, «＋» создаёт узел сразу в нужной колонке |
| **dash** | плитки (узлы, связи, блокеры, вехи, «можно брать сейчас», критический путь, черновики), топ-12 по весу, разбивки по статусам и категориям, критический путь списком, реестр блокеров таблицей |

Фильтр страницы (`matchFilter`) общий для всех типов: категории, статусы, типы, пользовательские поля,
«только с блокерами», полнотекстовый поиск по названию, подписи, id, описанию, значениям полей и вехам.

⚠️ **Костыль, который надо знать:** в блоке «ДАШБОРД» функция `pageNodes` **переопределяется**
(monkey-patch) поверх исходной из a2, чтобы добавить фильтры `crit`/`ready` только для холста.
Выглядит так:
```js
const _pageNodes = pageNodes;
pageNodes = function (pg) { /* ... _pageNodes(pg) + crit/ready ... */ };
```
Если будете переносить код — не потеряйте этот блок и не вызовите `pageNodes` до него.

## 8. UI-соглашения

### CSS
- Все цвета — через переменные в `:root` (`--ink`, `--ink2`, `--muted`, `--line`, `--accent`, `--red/amber/green/grey` + их `-bg`/`-br` варианты, тени `--sh1..3`).
- Компоненты: `.btn` (+`.pri`/`.act`/`.dgr`/`.sm`/`.ico`), `.chip`, `.pill`, `.card`, `.tile`,
  `.menu > .mlist > .mi`, `.pgi` (строка сайдбара), `.crow` (строка редактора схемы), `.picker`/`.pk` (список чекбоксов).
- Узел холста: `.nd` + `.shp-pill` / `.shp-di`; состояния `.sel`, `.dim`, `.anc`, `.dsc`, `.drag`, `.droptgt`.
- `.noview` — элемент, который вырезается в режиме просмотра.

### Правила, которые уже стоили отладки (⚠️ ГРАБЛИ)
1. **`.pill` занят статус-пилюлями.** Формы узлов называются `shp-pill` / `shp-di`. Не называть классы формы `pill`.
2. **У `.nd` не должно быть `overflow:hidden`** — иначе порты (вынесены на `-7px` за границу) перестают
   ловить мышь. Обрезка текста делается на `.nt`/`.ns` через `-webkit-line-clamp`.
3. **`classList.toggle(cls, force)` с `undefined`** во втором аргументе работает как обычный toggle.
   Всегда приводить к boolean: `toggle('hidden', !!cond)`.
4. **Перерисовка форм крадёт фокус.** Текстовые поля меняют данные по `input` **без** перерисовки
   (только `save()` + мягкое обновление холста); `select`/`checkbox` — по `change` с полной перерисовкой.
5. **Зум колесом надо клампить** по фактору (`0.82…1.22`), иначе одно синтетическое событие
   с `deltaY = -300` улетает в максимум.
6. **`CSS.escape(id)`** обязателен во всех селекторах по id узла — id пользовательские.

## 9. Экспорт, импорт, viewer

| Направление | Формат | Заметки |
|---|---|---|
| Экспорт | JSON проекта | `JSON.stringify(P, null, 1)`, полный дамп |
| Экспорт | Бэкап всех проектов | `{graphstudio:1, exported, projects:[...]}` |
| Экспорт | CSV узлов / вех / связей | разделитель `;`, BOM в начале — Excel-ru открывает без плясок |
| Экспорт | Markdown | сгруппировано по шагам, вехи таблицей — для Obsidian |
| Экспорт | **viewer.html** | см. ниже |
| Импорт | JSON Graph Studio | как новый проект или слияние в текущий по `id` |
| Импорт | JSON Roadmap Studio (старый) | автоопределение по `nodes[0].deps`/`nodes[0].t`, конвертер `fromLegacy()` |
| Импорт | CSV узлов | по `id` или `name`; статусы/категории матчатся и по ключу, и по русскому названию |

**Как работает viewer.html.** В самом начале скрипта снимается `TEMPLATE = '<!DOCTYPE html>\n' +
document.documentElement.outerHTML` — снимок собственного исходника **до** любых мутаций DOM.
При экспорте в этом снимке подменяется содержимое `<script id="seed">` на текущий проект
и `window.VIEWER=false` → `true`. Получается самодостаточный файл только для чтения.

⚠️ Из-за этого трюка: **любой код, который мутирует DOM, должен выполняться после снятия `TEMPLATE`**
(сейчас это гарантировано — снимок первой строкой скрипта).
И в исходнике нельзя писать литерал `</script>` — он собирается конкатенацией `'<' + '/script>'`.

При удалении страницы удалять `node.p[pageId]` у всех узлов; при импорте — отбрасывать позиции
для несуществующих страниц.

### P2-5. Автолинковка по тексту
В описании узла синтаксис `[[id]]` превращается в кликабельную ссылку на другой узел
и опционально предлагает создать связь.

### P2-6. Презентационный режим (перенести из просмотрщика)
В `roadmap_full_2.html` уже реализован: шаги по колонкам с перелётом камеры, затемнением остального
и панелью навигации. Перенести в Graph Studio для страниц-холстов.

## 12. Как разрабатывать и проверять

### Правила кода
- Без сборки, без зависимостей, без сети. Только то, что есть в браузере.
- Функции глобальные, именование как в существующем коде: `renderX`, `buildX`, `openX`, `showX`, `paintX`.
- Мутация данных → `snapshot()` или `snapNow()` **до** изменения → изменение → `gInval()` (если тронули граф)
  → `save()` → перерисовка.
- Любой пользовательский текст в HTML — через `esc()`. Исключение: поля, где HTML разрешён осознанно
  (`page.canvas.intro`, `project.desc` в справке).
- Русский язык интерфейса, профессиональные термины без перевода.

### Регрессионный чеклист (прогонять после существенных правок)
1. Открытие файла с пустой IndexedDB → создаётся стартовый проект, открывается «Обзор».
2. Холст: панорама колесом, зум `Ctrl`+колесо, drag узла, рамка выделения, связь от порта,
   клик по стрелке, контекстное меню, `Ctrl+G`, `Delete`, `Ctrl+Z`.
3. Переключение всех типов страниц, создание новой страницы каждого типа.
4. Таблица: правка в ячейке, сортировка, группировка, выбор колонок.
5. Канбан: перетаскивание карточки между колонками меняет поле.
6. Схема: добавить статус → он появился в селекторах; удалить используемую категорию → предупреждение.
7. Экспорт JSON → импорт как новый проект → совпадает число узлов и связей.
8. Экспорт `viewer.html` → открыть → нет кнопок правки, карта рисуется, карточка открывается.
9. Перезагрузка страницы → проект и правки на месте.

### Автотесты (рекомендуемый способ)
Playwright + Chromium, файл открывается по `file://`. Шаблон:

```js
const {chromium} = require('playwright');
const b = await chromium.launch();
const p = await b.newPage({viewport: {width: 1680, height: 1000}});
p.on('pageerror', e => console.log('PAGEERROR:', e.message));
await p.goto('file:///path/graph_studio.html');
await p.waitForTimeout(1500);
await p.evaluate(() => closeModal());          // справка при первом запуске
// дальше — обычные клики + p.evaluate() для проверки состояния (P, UI, DOM)
```

Полезно: состояние приложения полностью доступно из `page.evaluate` через глобальные `P`, `UI`, `G()`,
поэтому проверки пишутся коротко: `await p.evaluate(() => P.links.length)`.

## 14. Глоссарий

| Термин | Значение |
|---|---|
| **Узел** | элемент графа: продукт, этап, гейт, шаг процесса |
| **Гейт** | узел-условие, без которого не поедет остальное; рисуется скруглённым |
| **Связь** | направленная зависимость «источник должен быть готов, чтобы поехал приёмник» |
| **Жёсткая связь** | блокирующая: влияет на слой, вес и критический путь |
| **Мягкая связь** | нужна для полноты, но не для старта; на расчёты не влияет |
| **Вес узла** | сколько узлов транзитивно откроется, если закрыть этот |
| **Шаг / колонка** | глубина зависимости, а не дата |
| **Веха (check)** | пункт работ внутри узла; может быть помечен как жёсткий блокер |
| **Страница** | представление одного и того же пула узлов: холст, таблица, канбан, дашборд |
| **Схема** | пользовательская конфигурация: типы узлов, статусы, категории, типы связей, свои поля |

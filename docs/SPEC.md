## Changelog 2.7.0 (10.09.2026) — слияние правок доски

**Что изменилось в модели конфликта.** Оптимистическая блокировка осталась: сервер
по-прежнему отвечает 409 на устаревший `baseVersion`. Изменился разбор ответа на клиенте.

`mergeJamDocs(base, mine, theirs)` в `src/main.js` пробует слить сам и возвращает
документ или `null` — «нужен разговор с человеком». Слияние срабатывает, когда
`jamRest(mine) === base.rest`, то есть мои правки ЦЕЛИКОМ лежат в объектах досок
и в позициях узлов на них. Иначе автоматика потеряла бы то, чего не умеет сливать,
и показывается прежний диалог.

**Слепок базы** живёт в `cloud.js` рядом с `baseline` (`setBaseline(fp, jam)`,
`getBaseJam()`) и пересчитывается в тех же точках. Он содержит: `items` — страница →
id объекта → JSON объекта; `npos` — позиции узлов на досках; `rest` — весь документ
с вырезанными объектами досок и этими позициями.

**Почему трёхстороннее.** Имея только «моё» и «серверное», нельзя отличить «я удалил
объект» от «коллега его добавил»: в обоих случаях он есть у них и нет у меня. Слияние
наугад либо воскрешает удалённое, либо стирает чужое. База снимает неоднозначность.

**Правила слияния** для каждой доски: было в базе и нет у меня → удаляю у них;
у меня отличается от базы → кладу поверх их; я не трогал → как у них. Порядок
наложения берётся мой для тронутого, их — для остального. Конфликт остаётся ровно
на объекте, который правили оба, и там побеждает последний.

**Не CRDT сознательно.** У объектов доски есть `id`, и этого достаточно; CRDT потребовал
бы другой модели документа, другой истории версий и другого протокола — при том что
единственный неразрешимый случай (двое правят один стикер) он всё равно решает
произволом, только менее понятным.

## Changelog 2.6.0 (10.09.2026) — доска в коннекторе

`server/src/mcp/doc.js` получил блок операций над доской, `tools.js` — пять
инструментов (в реестре стало 29): `jam_add`, `jam_update`, `jam_delete`,
`jam_read`, `jam_arrange`.

**Почему `jam_read` отдельно от `get_board`.** Объекты доски — единственная часть
документа, которая может весить больше всего остального. `get_board` отдаёт по ней

иначе отказ: стрелка к узлу, которого на доске нет, нарисовалась бы в пустоту.

**`jam_arrange`** — один инструмент с `enum` из девяти операций. Коннекторы и рисунки
в выравнивание не входят: у них нет собственного прямоугольника.

**Два числа в отчёте `jam_delete`.** `removed` — сколько удалено по просьбе,
`connectors_removed` — сколько коннекторов ушло следом. Считать их одним числом
значило бы отвечать «удалено 3» на просьбу удалить один объект.

## Changelog 2.5.0 (10.09.2026) — свободная доска

Новый тип страницы `jam` рядом с `canvas`, `space`, `table`, `board`, `dash`.
Существующие страницы не тронуты.

**Где живут объекты.** В самой странице: `page.jam = {items: [], bg}`. Не в корне
документа — там уже лежат `P.notes` и `P.frames`, у которых НЕТ привязки к странице,
из-за чего одна заметка видна на каждой пространственной странице. Повторять это
в масштабе доски нельзя. Побочная выгода: удаление страницы уносит объекты
по построению, осиротевших не бывает, а `duplicatePage()` копирует содержимое.

**Порядок наложения — это порядок в массиве `items`.** Отдельного поля `z` нет:
нечему разъехаться, нет ничьих при равных значениях, нет перенормировки,
отмена бесплатна, и SVG-диалект для коннектора ляжет на него один в один.

**Объект:**

```jsonc
{
  "id": "i_ab12",
  "kind": "sticky",      // sticky | shape | text | draw | conn | section
  "x": 120, "y": 80, "w": 180, "h": 180,
  "rot": 0,              // градусы, необязательно
  "fill": "#ffd93b",     // значением, а не ключом схемы: у доски схемы нет
  "stroke": "", "sw": 3,
  "text": "…",
  "lock": 0,
  // только kind:'draw' — точки ОТНОСИТЕЛЬНО x,y, целые, через пробел
  "d": "0,0 8,3 15,9",
  // только kind:'shape'
  "shape": "roundrect",  // rect|roundrect|ellipse|diamond|triangle|star|arrow
  // только kind:'conn' — конец ссылается на объект, на узел графа или на точку
  "a": {"item": "i_x", "side": "r"},
  "b": {"node": "LIC", "side": "c"},
  "style": "curve",      // curve | ortho | line
  "capA": "none", "capB": "arrow"
}
```

`draw.d` — строка, а не массив объектов, сознательно: в 3–5 раз компактнее,
быстрее в `JSON.parse`, а перемещение штриха это правка ДВУХ чисел (`x`, `y`),
а не переписывание всего пути. Документ уезжает целиком в стек отмены, в IndexedDB,
на сервер и в живой канал на каждую правку — объём здесь не мелочь.

**Три предиката вместо одного** (`src/main.js`):
- `isSpatial` — «страница с камерой»: зум, панорама, перетаскивание, копипаст,
  клавиши, курсоры коллег. Доска входит.
- `isGraphCv` — «холст графа»: диспетчер отрисовки, экспорт картинки, клавиша `N`.
- `isJam` — доска.

Из 24 мест, где стоял `isSpatial`, на `isGraphCv` переведены ровно четыре.
Остальные действительно означали «страница с камерой».

**Коннектор доски — не связь графа.** Он лежит в `page.jam.items`, а `hasCycle()`
читает только `P.links`. Поэтому на доске стрелки могут образовывать циклы, а вес
узлов, слои и критический путь от них не меняются. Это единственное место, где две
модели встречаются, и оно должно оставаться видимым: коннектор между двумя
карточками узлов НЕ создаёт зависимости.

**Инструмент — состояние руки, а не свойство доски.** `JAM` живёт на уровне модуля
рядом с `drag`/`ptrs` (не внутри `wireCanvas`: она зовётся на каждую отрисовку)
и НЕ уезжает в документ. `gotoPage()` сбрасывает его: утёкший на холст-граф «ластик»
означал бы, что ветка инструмента в `onDown` перехватывает нажатия там, где её не ждут.

**Порядок веток в `onDown`.** Ветка инструмента идёт ПЕРВОЙ — до панорамы и до всех
попаданий: нажатие пером по стикеру должно рисовать, а не тащить его. Ресайз объекта
(`.jrs`) идёт до самого объекта — по той же причине, по которой `.nd .rs` идёт до `.nd`.

**Что доска НЕ зовёт:** `paintNotes()` и `paintFrames()`. Они глобальные — на доску
вывалились бы все заметки и области проекта.

**Габариты сцены — `sceneBoxes(pg)`.** `fitAll()`, `drawMini()` и `buildPreview()`
строили список по одним `cvNodes`. На доске без узлов графа это означало бы: камера
сбрасывается в `{40,40,1}` при каждом открытии, миникарта пуста, а превью возвращает
`undefined` — что сервер понимает как «не трогай прежнее», и картинка доски на главной
замерла бы навсегда.

**Рисование.** Прореживание на лету (не ближе `2/v.k` мировых единиц — порог в мировых,
чтобы не зависеть от зума) плюс упрощение по Рамеру—Дугласу—Пейкеру на отпускании,
ε = 0.6. Сорок событий мыши дают штрих из 21 точки и 221 байта.

**Коннектор для Claude** знает вид `jam`: `PAGE_KINDS` и `enum` в схеме инструментов,
`addPage` заводит `page.jam`, `visibleOn` считает узел присутствующим только при наличии
координаты (как на схеме), `place_nodes` работает и на доске. `summarize` отдаёт
`jam_items` и `jam_kinds`, но НЕ сами объекты: их бывает больше, чем всего остального
документа, и один `get_board` сжёг бы контекст целиком.

### Починено попутно

| Что | Было |
|---|---|
| `client_max_body_size` в `docker/nginx.conf` | Директивы не было → умолчание nginx 1 МБ при `bodyLimit` 32 МБ в Fastify. 413 приходил СТРАНИЦЕЙ, `api.js` разбирал её как JSON |
| Размер узла из `place_nodes` | Коннектор писал в `n.sz[pageId]`, редактор читает `n.p[pageId].w/h`. `migrateNodeSizes()` переносит при открытии |
| Дублирование страницы | `clone(pg)` не копировал `n.p[старыйId]` — копия холста приходила пустой |
| Удаление страницы | `n.p[pageId]` оставался мусором в документе и уезжал в каждый экспорт |
| `add_page` с незнакомым видом | Молча создавал `canvas` и отвечал успехом |
| Глубина отмены | Только 60 шагов без учёта размера: доска с рисунками держала бы во вкладке десятки мегабайт строк. Добавлен бюджет 24 МБ |
| Живой канал | Документ рассылался целиком всем на каждое сохранение. Сверх 256 КБ уходит `{t:'stale'}`, клиент догружает сам |

## Changelog 2.4.0 (09.09.2026) — история: находимая и без потолка

Точки входа: пункт `#navHistory` в подвале боковой панели (виден только у серверной
доски), кликабельный номер версии в `#saveState`, команда в палитре. Кнопка внутри
«Экспорта и импорта» осталась, но искать историю там никто не будет.

Хранение (миграция 006): документ версии лежит в `board_versions.doc_gz` (gzip,
3–8× в зависимости от доски); старые строки с текстом в `doc` читаются как раньше —
`versionDoc(row)` разбирает оба случая. Потолок в 40 версий заменён прореживанием
по возрасту: всё за 7 дней, час — до 30 дней, день — до года, неделя — дальше;
первая и последняя версии не удаляются никогда. Прореживание запускается только
когда версий больше 150 (`THIN_AFTER`): сохранение идёт раз в секунду активной
правки, и гонять его на каждой было бы расточительством.

Почему не git (рассматривался): это второе хранилище рядом с SQLite со своей
историей согласованности и своим бэкапом; коммит на каждое сохранение — это git
как база под конкурентную запись, чем он не является; а главное — выигрыш git
в текстовых диффах здесь не работает: документ это один JSON-блоб, осмысленная
разница в котором поузловая. Семантическую подпись правки клиент и так считает
сам (`summarize` в main.js), и она полезнее `git diff`.

## Changelog 2.3.0 (09.09.2026) — доработки коннектора

`server/src/mcp/import.js` — импорт проекта целиком. Три правила, ради которых он
и появился: идентификаторы узлов сохраняются КАК ЕСТЬ (произвольные строки,
кириллица законна); ни одна связь не теряется молча (нет типа — тип заводится
и попадает в отчёт); ничего не создаётся сверх того, что есть в файле.
Переименование возможно только при столкновении id внутри самого файла — тогда
переписываются связи и позиции. Ответ — отчёт `{nodes_created, nodes_renamed,
links_created, links_dropped, pages_created, warnings}`, есть `dry_run`.

`summarize(doc, {layout, pagesOnly})` — раскладка в ответе `get_board`:
`lane` и `positions`/`sizes` у узлов, у холстов `nodes_pinned` (сколько узлов имеют
сохранённую позицию) и `nodes_visible` (сколько проходит фильтр страницы —
`visibleOn()` повторяет `matchFilter`/`pageNodes` приложения). Числа расходятся,
когда фильтр отсекает узлы, у которых координаты уже сохранены.

Камера: приложение не пишет её в документ с 1.x, но в проектах из старых файлов
поле `page.view` оставалось и ездило в каждом экспорте. `migrateLegacyViews()`
в main.js переносит такое значение в localStorage при открытии и удаляет из документа.
`include_layout` продолжает отдавать `view` с пометкой `legacy: true`, пока доску
не переоткрыли.

Правка, не изменившая документ, НЕ сохраняется: `ctx.edit` сравнивает снимок до и после
(до простановки `updated`, иначе разница есть всегда) и отвечает `changed: false`.

`update_nodes` принимает `lane`; `updatePage` при укорачивании `lanes` возвращает
узлы из исчезнувших колонок на авто. Поле `lane` общее для доски, а не постраничное —
так устроен документ.

Миграция 005: `boards.pages_count` — чтобы список досок не читал документы целиком
ради одного числа. Заполняется в единственной точке записи (`counts()` в boards.js).

Аудитория токена приводится к одному виду (`normResource`): клиенты присылают ресурс
то с путём, то без, и разные написания одного и того же дали бы токен, который сервер
сам же не примет. Чужой ресурс отклоняется сразу (`invalid_target`).

## Changelog 2.2.0 (09.09.2026) — коннектор для Claude (MCP + OAuth)

`server/src/mcp/` — три файла: `doc.js` (операции над документом), `tools.js`
(23 инструмента), `server.js` (JSON-RPC поверх HTTP). `server/src/oauth.js` —
свой сервер авторизации. Миграция 004: `oauth_clients`, `oauth_codes`, `oauth_tokens`.

**Адреса** (nginx проксирует их в api отдельными location — иначе SPA-фолбэк
отдал бы index.html там, где клиент ждёт JSON):
`/mcp`, `/oauth/{authorize,token,register,revoke}`,
`/.well-known/{oauth-protected-resource,oauth-authorization-server,openid-configuration}`.

**Что реализовано из спецификации:** RFC 9728 (метаданные ресурса), RFC 8414
(метаданные AS), RFC 7591 (регистрация клиента), OAuth 2.1 code+PKCE S256,
RFC 8707 (привязка токена к ресурсу), RFC 9207 (`iss` в ответе). Секреты и токены
лежат хэшами. Протокол MCP отвечает и «старым» ревизиям с `initialize`
(2025-03-26 … 2025-11-25), и текущей 2026-07-28 (`server/discover`, версия в каждом
запросе): клиенты Claude бывают разных поколений.

**Правка идёт общим путём.** `boards.js` отдаёт `saveBoard`/`createBoard`, и через них
ходят и браузер, и MCP. Поэтому правка из Claude попадает в историю с автором
и рассылается по живому каналу в открытые вкладки без единой отдельной строчки.

**Исключение из правила «сервер документ не разбирает».** `mcp/doc.js` формат знает —
иначе править было бы нечего. Ограничение, которое делает исключение безопасным:
неизвестные поля не трогаются никогда. Объекты не пересобираются, присваиваются
только явно перечисленные поля. Проверено тестом: чужое поле в узле переживает
правку из MCP.

**PUBLIC_URL** — issuer OAuth и имя ресурса MCP. Локально переопределяется
`GRAPH_STUDIO_PUBLIC_URL` (verify.sh и CI ставят `http://127.0.0.1:8081`).
Разъехавшийся адрес означает, что сервер не примет собственные токены.

## Changelog 2.1.0 (09.09.2026) — совместная работа, история, палец, файлы в онлайн

**Живой канал.** `server/src/live.js` — комнаты по доске поверх `@fastify/websocket`,
адрес `GET /api/boards/:id/live`. Права спрашиваются те же, что и на чтение доски.
Сообщения: `hello` (кто я, кто здесь, версия), `peers`, `cursor`, `update`.
`update` несёт документ ЦЕЛИКОМ вместе с собой — иначе каждая правка превращалась бы
в N ответных GET на те же байты. Строка сообщения собирается конкатенацией, чтобы
уже сериализованный документ не проходить через `JSON.stringify` второй раз.

Клиент — `src/live.js`: переподключение с растущей паузой, курсор не чаще 60 мс.
`onLiveUpdate` в `main.js` применяет чужую правку ТОЛЬКО когда своя очередь пуста
(`cloud.hasPending()`); иначе молчит и даёт отправке упереться в 409. Признаком
«есть неотправленное» служит очередь, а НЕ `UI.dirty`: dirty означает «не выгружено
в файл» и после сохранения не сбрасывается.

**История.** Миграция 003, таблица `board_versions` (доска, версия, время, автор,
подпись, документ). Хранятся последние 40 на доску, прореживает код при записи.
Подпись «что поменялось» считает КЛИЕНТ (`summarize`/`fingerprint` в main.js) и шлёт
вместе с PUT: сервер документ не разбирает. Эндпоинты `/versions`, `/versions/:v`,
`/versions/:v/restore`. Возврат пишет НОВУЮ версию поверх, историю не трогает.
`UI.viewVersion` — режим просмотра старой версии: доска только читается, живые
обновления её не подменяют.

**Файлы.** Блок File System Access и папка-хранилище удалены целиком. Осталась
`safeName` и экспорт/импорт. `importText(txt, mode)` отделён от выбора файла, чтобы
путь «текст → доска на сервере» проверялся тестом. `backupAll` собирает доски
С СЕРВЕРА плюс локальные проекты; кэш открытых досок (`srv_<id>` в IndexedDB)
исключается из обоих списков — иначе каждая открытая доска появлялась бы ещё
и в разделе «на этом компьютере».

**Указатель.** Холст переведён с `mouse*` на `pointer*`, `touch-action:none` на `#cv`.

## Changelog 1.5.0 (09.09.2026) — свободная схема

Новый тип страницы `space` рядом с `canvas`. Существующий холст не тронут.

Разделение смысла, чтобы не размыть ключевое продуктовое решение:
- `canvas` — «в каком порядке это физически может поехать»: колонка = глубина
  зависимости, видны все узлы проекта, прошедшие фильтр, раскладку считает граф,
  стрелка всегда идёт слева направо (это и есть чтение «сначала это, потом то»);
- `space` — «как это устроено»: свободная схема, на ней лежит только то, что положили,
  позиции и размеры руками, стрелки выбирают сторону по расположению узлов.

`P.links` остаётся ОДНИМ графом на проект: «просто стрелка» — это не другая страница,
а другой тип связи. Ацикличность по-прежнему обязательна на обеих страницах.

- **`isSpatial(pg)`** развёл 18 проверок `pg.kind === 'canvas'`, которые на самом деле
  про механику холста (камера, перетаскивание, копипаст, клавиши, экспорт картинки),
  от тех, что про семантику зависимостей (колонки, `n.lane`, 📌, критический путь).
- **Присутствие узла на схеме = наличие `n.p[pageId]`.** Иначе на неё вываливались бы
  все узлы проекта кучей. Положить существующий узел — «↧ Положить узел» в панели страницы.
  Побочно: пункт бэклога P2-4 «чистка мусора в node.p» перестал быть чисткой —
  `n.p` теперь носитель смысла, удалять его можно только вместе со страницей.
- **Размер узла — `n.p[pageId].w/h`**, рядом с позицией, и только на схеме.
  В корень ноды не пишем: это повторило бы техдолг `n.x/n.y`, когда размер один
  на все страницы. Читатели размера (`nsize()`) заменили 12 мест с `n.w || NW`.
  На холсте-зависимостях ручки ресайза нет: там раскладка считается из констант
  `NW`/`NH`, и разные размеры узлов её сломали бы.
- **Сетка следует за камерой.** Точки нарисованы фоном на `#cv`, который камерой
  не двигается, — раньше они стояли намертво и «плыли» относительно узлов при панораме.
  Теперь `applyView()` пересчитывает `background-size`/`background-position`,
  а шаг удваивается или делится, чтобы на любом зуме точки не сливались и не расползались.
- Четыре места падали на схеме с TypeError, потому что читали `pg.canvas` без проверки:
  `nodeHTML`, `ctxMenu`, `buildCanvasSVG`, `paintLanes`. Диспетчер `renderPage()`
  раньше молча рисовал дашбордом всё неизвестное — теперь пишет, чего не знает.

Новый проект пишется файлом в папку сразу (`vaultAddProject`, дергается при создании из шаблона). Смена папки (`chooseVault`) пересканирует и подтягивает файлы новой папки, убирая проекты старой из кэша. «Обновить из папки» (`refreshVault`), «Отключить» (`disconnectVault`). На boot — авто-подтяжка, если доступ к папке уже выдан (`queryPermission==='granted'`, без запроса). IndexedDB становится кэшем папки; id проектов из `.json` стабильны (у файлов без нативного id — `vf_<имяФайла>`). Кнопка `#pVault` + строка `#vaultStatus` на стартовом экране. Только Chrome/Edge (secure context); без FSA — кнопка скрыта.
- **Записи в файл сериализованы** (`_writeLock`) — одновременные `createWritable` по одному файлу иначе конфликтуют и могут обнулить файл.
- **Откат без FSA** (file://, Safari, Firefox): `openProjectFile`→`importJson`, `saveProjectToFile`→скачивание. Ничего не ломается.
- **Фасетный фильтр** (`facetCounts` + `buildFilterMenu`): у каждого значения фильтра — число подходящих узлов текущей страницы (`pageNodes(pg)`); пустые для страницы значения скрыты, переключатель «Показать все значения» (`UI.filterShowAll`) их раскрывает. Убирает путаницу «почему на доске X видна доска/категория Y» — модель пула не меняется, только релевантность списка.
- **Инлайн-создание из инспектора.** В селектах правки узла добавлен пункт «＋ Новый…»: тип/статус/категория (`createSchemaItem`), колонка холста (`createLane` — добавляет подпись колонки и закрепляет узел), значение своего select-поля (`createFieldOption`). Ключ генерится из названия (`schemaKey`), цвет статуса/категории берётся из `SCHEMA_PALETTE` (`nextColor`, первый неиспользованный). Полное оформление (цвет/форма/переименование/удаление) — по-прежнему в «Схеме проекта».

⚠️ **Грабли, стоившие отладки:** `const FSA` изначально был объявлен в блоке FSA (ниже по файлу), а верхнеуровневая привязка кнопки `#pOpenFile` ссылалась на него выше → **TDZ ReferenceError** валил весь скрипт до `boot()`, приложение не стартовало (на всех origin). Урок: любые `const/let`, на которые ссылается верхнеуровневый код, объявлять **до** первого использования (сейчас `FSA` объявлена рядом с `VIEWER`).

## 1. Что это

**Graph Studio** — редактор графов зависимостей: роадмапы, карты разблокировок («что чем заблокировано»),
процессы и любые схемы, где важны узлы, связи между ними и производные метрики (вес узла, критический путь, слои).

Одностраничное приложение в **одном самодостаточном HTML-файле**. Никакого бэкенда, сборки, npm, сети.
Открывается двойным кликом из файловой системы (`file://`), работает офлайн.

### Кто пользователь
Product manager, который держит в голове зависимости между продуктами и этапами и должен уметь:

- быстро ответить «что нас держит» и «что откроется, если закрыть X»;
- показать карту на совете директоров без подготовки слайдов;
- править данные там же, где смотрит, а не в отдельной таблице;
- завести вторую-третью тему (не только текущий роадмап) в том же инструменте.

### Ключевые продуктовые решения (не менять без веской причины)
1. **Колонка на холсте = глубина зависимости, а не календарь.** Это принципиально отличает инструмент
   от диаграммы Ганта: он отвечает на вопрос «в каком порядке это физически может поехать».
2. **Вес узла** = размер транзитивного множества потомков. Это метрика приоритета: «закрыв это, разблокируешь N».
3. **Типы связей делятся на блокирующие и неблокирующие.** Только блокирующие влияют на слои, вес и критический путь.
4. **Один пул узлов, много представлений.** Страницы (холст/таблица/канбан/дашборд) — это фильтры + способ отрисовки,
   а не отдельные наборы данных.
5. **Схема настраивается пользователем**, а не захардкожена: типы узлов, статусы, категории, типы связей, свои поля.

- `links[].from/to` обязаны указывать на существующие `nodes[].id`. Битые связи молча игнорируются

## 4. Хранилище и жизненный цикл данных

**IndexedDB** база `graphstudio`, версия 1, три store:

| Store | keyPath | Что лежит | Статус |
|---|---|---|---|
| `projects` | `id` | целые проекты | используется |
| `meta` | `k` | `{k:'last', v:projectId}`, `{k:'seen', v:1}` | используется |
| `snaps` | `id` | `{id, proj, name, at, nodes, links, data}` — именованные снимки версий | **задействован в 1.1** (P0-1) |
| `meta` | `k` | +`{k:'theme', v:'dark'\|'light'}` в 1.1 | тема оформления |

- `save(immediate)` — дебаунс 420 мс, ставит `P.updated = today()`, пишет весь проект целиком.
  Полная перезапись каждый раз: при 104 узлах это ~200 КБ на запись, приемлемо; на 1000+ узлов надо думать.
- `snapshot()` — кладёт `JSON.stringify(P)` в `undoS`, глубина 60, дебаунс 650 мс
  (чтобы ввод текста не забивал стек). `snapNow()` — форсированный снимок перед дискретным действием.
- `undo()` / `redo()` — полная замена объекта `P`, затем `gInval()` + перерисовка.
- При старте (с 2.0.0): открыть БД → загрузить локальные проекты → спросить сервер, кто мы
  (`cloud.loadAccount()`) → разобрать адрес (`routeBoot()`). Если адрес ни на что конкретное
  не указывает: со входом — `home.showHome('all')`, без входа но с локальными проектами —
  `home.showHome('local')`, иначе витрина `home.showLanding()`.
  **Последний проект молча не открывается**: человек попадал сразу в свою вчерашнюю доску
  и не понимал, где он и что здесь ещё есть.
- Источник правды с 2.0.0 — сервер. IndexedDB остаётся кэшем открытой доски и домом
  для проектов прежней версии; `meta.last` больше не решает, что показать на старте.

**Режим просмотра**: `window.VIEWER = true` (ставится в экспортированном `viewer.html`).
В этом режиме IndexedDB не трогается вообще, проект берётся прямо из `#seed`,
все элементы с классом `.noview` удаляются из DOM.

## 5. Ядро: граф и метрики

`G()` — единственная точка вычисления производных величин. Результат кэшируется в `_g`,
инвалидируется через `gInval()` **после любой правки узлов, связей или типов связей**.

Возвращает:

| Поле | Что |
|---|---|
| `kids[id]` | `[{id, lid, soft}]` — исходящие связи |
| `par[id]` | `[{id, lid, soft}]` — входящие связи |
| `hardPar[id]` | массив id только по блокирующим связям — вход для слоёв |
| `layer[id]` | глубина: `0`, если нет блокирующих входящих; иначе `max(layer(предков)) + 1` |
| `DESC[id]` / `ANC[id]` | `Set` транзитивных потомков / предков (по всем связям) |
| `W(id)` | **вес** = `DESC[id].size` |
| `crit` | `Set` критического пути |

**Критический путь** — цепочка от корня с максимальной суммой `DESC.size + 1` вдоль блокирующих связей.
Считается мемоизацией `f(id) = max(f(детей)) + DESC[id].size + 1`, стартовая точка — узел без входящих
с максимальным `f`.

`stepOf(n)` = `n.lane`, если задан вручную, иначе `layer[n.id]`.

⚠️ Защита от циклов в `layer()` — флаг `seen`, который при цикле вернёт `0`. То есть даже если цикл
как-то просочится, приложение не зависнет, но раскладка будет неверной.

## 6. Холст

### Система координат
- **Мир** — координаты узлов (`x`,`y` в пикселях при zoom = 1).
- **Камера** `view() = {x, y, k}`, своя на каждую страницу, живёт в `UI.view[pageId]` (в памяти),
  а между сессиями — в `localStorage` под ключом `gs_view:<projectId>:<pageId>` (с 1.2.1).
  Это личное состояние человека: в документ проекта оно не пишется, иначе панорамирование одного
  участника конфликтовало бы с правками другого. `page.view` из старых файлов читается как запасной источник.
- Применяется одним трансформом на `#scene`: `translate(x,y) scale(k)`.
- `toWorld(clientX, clientY)` — обратное преобразование с учётом `getBoundingClientRect()` контейнера.
- `#edges` — SVG размером 1×1 с `overflow:visible`; так связи рисуются в мировых координатах,
  включая отрицательные, без гигантского холста.

### Константы
```
NW = 212, NH = 74          размер узла
COLGAP = 108               между колонками
SUBGAP = 34                между подколонками внутри колонки
ROWGAP = 12                между узлами по вертикали
PADX = 60, PADY = 70       отступы раскладки
GRID = 8                   шаг привязки при перетаскивании
zoom: 0.08 … 3             клампы масштаба
wheel-zoom factor: 0.82 … 1.22   (иначе трекпад/синтетические события дают скачок)
```

### Авто-раскладка `autoLayout(nodes)`
Пятиэтапный алгоритм (перенесён из исходной визуализации, менять осторожно):

1. **Колонка** каждого узла = глубина по блокирующим связям внутри видимого подграфа
   (`n.lane` перебивает расчёт). Пустые колонки схлопываются, но исходный номер сохраняется
   для подписи (`capIdx`).
2. **Локальный уровень внутри колонки** — зависимости между узлами одной колонки → подколонки.
3. **Первичная сортировка**: по весу убыв., затем по категории.
4. **6 итераций барицентра** — попеременно слева направо и справа налево, узел тянется к среднему
   индексу своих соседей. Это то, что распутывает стрелки.
5. **Позиционирование**: подколонки внутри колонки, вертикальное центрирование группы.

Возвращает `pos{id → {x,y}}` и `lanes[{x, idx, h}]` для подписей и пунктирных разделителей.

### Режимы раскладки страницы
- `layout: 'auto'` — позиции считаются каждый рендер; узел с `p[pageId]` берёт свою закреплённую позицию
  и получает бейдж 📌. Перетаскивание в этом режиме **закрепляет** узел.
- `layout: 'free'` — все позиции берутся из `p[pageId]`. Засев — `seedFreePositions(pg)`, только
  по явному действию (создание страницы, переключение раскладки). С 1.2.1 **отрисовка не сохраняет
  ничего**: узел без своей позиции берёт расчётную из авто-раскладки, но в документ она не пишется.

### Взаимодействия (`onDown` — единая точка входа)
Порядок проверок в `mousedown` важен, менять нельзя:

```
1. средняя кнопка / Space   → pan
2. .hit (толстая невидимая дорожка связи, 14px) → выбрать связь
3. .port                    → тянуть новую связь
4. .nd                      → выделение + drag узла (всех выделенных)
5. .fr .rs / .fr .fh        → resize / drag области
6. .stk .rs / .stk          → resize / drag заметки
7. пустое место             → рамка выделения (Shift — добавить к выделению)
```

Прочее:
- колесо — панорама; `Ctrl`/`Cmd` + колесо (и пинч на трекпаде) — зум к курсору;
- двойной клик по пустому — новый узел, по узлу — переименование на месте (`contenteditable`);
- правая кнопка — контекстное меню с подменю статусов и категорий;
- миникарта: клик и тяга перемещают камеру;
- при отпускании связи над узлом: `Shift` = второй тип связи из схемы.

## 7. Страницы

`renderPage()` — диспетчер: рисует панель страницы и вызывает `renderCanvas` / `renderTable` /
`renderBoard` / `renderDash`.

| Тип | Что умеет |
|---|---|
| **canvas** | всё из раздела 6; фильтры треков; переключатели «критический путь» и «доступное сейчас»; выбор типа связи по умолчанию; редактор подписей колонок |
| **table** | выбор колонок (ядро + любые пользовательские поля), сортировка кликом по заголовку, группировка по любому select-полю, правка в ячейках, мультивыделение с `Shift`/`Ctrl` |
| **board** | колонки по любому полю-списку (`status`, `cat`, `type`, `step`, `f.*`), перетаскивание карточки меняет значение поля, «＋» создаёт узел сразу в нужной колонке |
| **jam** | свободная доска: стикеры, фигуры, текст, рисунки от руки, коннекторы; объекты лежат в самой странице; узел проекта кладётся кнопкой «↧ Положить узел» |
| **dash** | плитки (узлы, связи, блокеры, вехи, «можно брать сейчас», критический путь, черновики), топ-12 по весу, разбивки по статусам и категориям, критический путь списком, реестр блокеров таблицей |

Фильтр страницы (`matchFilter`) общий для всех типов: категории, статусы, типы, пользовательские поля,
«только с блокерами», полнотекстовый поиск по названию, подписи, id, описанию, значениям полей и вехам.

⚠️ **Костыль, который надо знать:** в блоке «ДАШБОРД» функция `pageNodes` **переопределяется**
(monkey-patch) поверх исходной из a2, чтобы добавить фильтры `crit`/`ready` только для холста.
Выглядит так:
```js
const _pageNodes = pageNodes;
pageNodes = function (pg) { /* ... _pageNodes(pg) + crit/ready ... */ };
```
Если будете переносить код — не потеряйте этот блок и не вызовите `pageNodes` до него.

## 8. UI-соглашения

### CSS
- Все цвета — через переменные в `:root` (`--ink`, `--ink2`, `--muted`, `--line`, `--accent`, `--red/amber/green/grey` + их `-bg`/`-br` варианты, тени `--sh1..3`).
- Компоненты: `.btn` (+`.pri`/`.act`/`.dgr`/`.sm`/`.ico`), `.chip`, `.pill`, `.card`, `.tile`,
  `.menu > .mlist > .mi`, `.pgi` (строка сайдбара), `.crow` (строка редактора схемы), `.picker`/`.pk` (список чекбоксов).
- Узел холста: `.nd` + `.shp-pill` / `.shp-di`; состояния `.sel`, `.dim`, `.anc`, `.dsc`, `.drag`, `.droptgt`.
- `.noview` — элемент, который вырезается в режиме просмотра.

### Правила, которые уже стоили отладки (⚠️ ГРАБЛИ)
1. **`.pill` занят статус-пилюлями.** Формы узлов называются `shp-pill` / `shp-di`. Не называть классы формы `pill`.
2. **У `.nd` не должно быть `overflow:hidden`** — иначе порты (вынесены на `-7px` за границу) перестают
   ловить мышь. Обрезка текста делается на `.nt`/`.ns` через `-webkit-line-clamp`.
3. **`classList.toggle(cls, force)` с `undefined`** во втором аргументе работает как обычный toggle.
   Всегда приводить к boolean: `toggle('hidden', !!cond)`.
4. **Перерисовка форм крадёт фокус.** Текстовые поля меняют данные по `input` **без** перерисовки
   (только `save()` + мягкое обновление холста); `select`/`checkbox` — по `change` с полной перерисовкой.
5. **Зум колесом надо клампить** по фактору (`0.82…1.22`), иначе одно синтетическое событие
   с `deltaY = -300` улетает в максимум.
6. **`CSS.escape(id)`** обязателен во всех селекторах по id узла — id пользовательские.

## 9. Экспорт, импорт, viewer

| Направление | Формат | Заметки |
|---|---|---|
| Экспорт | JSON проекта | `JSON.stringify(P, null, 1)`, полный дамп |
| Экспорт | Бэкап всех проектов | `{graphstudio:2, exported, projects:[...], snaps:[...]}` — с 1.2.1 включает корзину и снимки версий; формат 1 читается по-прежнему |
| Экспорт | CSV узлов / вех / связей | разделитель `;`, BOM в начале — Excel-ru открывает без плясок |
| Экспорт | Markdown | сгруппировано по шагам, вехи таблицей — для Obsidian |
| Экспорт | **viewer.html** | см. ниже |
| Импорт | JSON Graph Studio | как новый проект или слияние в текущий по `id` |
| Импорт | JSON Roadmap Studio (старый) | автоопределение по `nodes[0].deps`/`nodes[0].t`, конвертер `fromLegacy()` |
| Импорт | CSV узлов | по `id` или `name`; статусы/категории матчатся и по ключу, и по русскому названию |

**Как работает viewer.html.** В самом начале скрипта снимается `TEMPLATE = '<!DOCTYPE html>\n' +
document.documentElement.outerHTML` — снимок собственного исходника **до** любых мутаций DOM.
При экспорте в этом снимке подменяется содержимое `<script id="seed">` на текущий проект
и `window.VIEWER=false` → `true`. Получается самодостаточный файл только для чтения.

⚠️ Из-за этого трюка: **любой код, который мутирует DOM, должен выполняться после снятия `TEMPLATE`**
(сейчас это гарантировано — снимок первой строкой скрипта).
И в исходнике нельзя писать литерал `</script>` — он собирается конкатенацией `'<' + '/script>'`.

## 12. Как разрабатывать и проверять

### Правила кода
- Без сборки, без зависимостей, без сети. Только то, что есть в браузере.
- Функции глобальные, именование как в существующем коде: `renderX`, `buildX`, `openX`, `showX`, `paintX`.
- Мутация данных → `snapshot()` или `snapNow()` **до** изменения → изменение → `gInval()` (если тронули граф)
  → `save()` → перерисовка.
- Любой пользовательский текст в HTML — через `esc()`. Исключение: поля, где HTML разрешён осознанно
  (`page.canvas.intro`, `project.desc` в справке).
- Русский язык интерфейса, профессиональные термины без перевода.

### Автотесты (рекомендуемый способ)
Playwright + Chromium, файл открывается по `file://`. Шаблон:

```js
const {chromium} = require('playwright');
const b = await chromium.launch();
const p = await b.newPage({viewport: {width: 1680, height: 1000}});
p.on('pageerror', e => console.log('PAGEERROR:', e.message));
await p.goto('file:///path/graph_studio.html');
await p.waitForTimeout(1500);
await p.evaluate(() => closeModal());          // справка при первом запуске
// дальше — обычные клики + p.evaluate() для проверки состояния (P, UI, DOM)
```

Полезно: состояние приложения полностью доступно из `page.evaluate` через глобальные `P`, `UI`, `G()`,
поэтому проверки пишутся коротко: `await p.evaluate(() => P.links.length)`.

## 14. Глоссарий

| Термин | Значение |
|---|---|
| **Узел** | элемент графа: продукт, этап, гейт, шаг процесса |
| **Гейт** | узел-условие, без которого не поедет остальное; рисуется скруглённым |
| **Связь** | направленная зависимость «источник должен быть готов, чтобы поехал приёмник» |
| **Жёсткая связь** | блокирующая: влияет на слой, вес и критический путь |
| **Мягкая связь** | нужна для полноты, но не для старта; на расчёты не влияет |
| **Вес узла** | сколько узлов транзитивно откроется, если закрыть этот |
| **Шаг / колонка** | глубина зависимости, а не дата |
| **Веха (check)** | пункт работ внутри узла; может быть помечен как жёсткий блокер |
| **Страница** | представление одного и того же пула узлов: холст, таблица, канбан, дашборд |
| **Схема** | пользовательская конфигурация: типы узлов, статусы, категории, типы связей, свои поля |

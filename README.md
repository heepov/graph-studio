# Graph Studio

Редактор графов зависимостей: роадмапы, карты разблокировок («что чем заблокировано»),
процессы и любые схемы, где важны узлы, связи и производные метрики — вес узла,
критический путь, слои.

**→ [graph.heeprod.ru](https://graph.heeprod.ru)**

Приложение целиком клиентское: нет бэкенда, нет аккаунтов, нет телеметрии.
Данные лежат в браузере (IndexedDB) и в обычных `.json`-файлах на вашем диске.
Сервер отдаёт только статику.

---

## Возможности

- **Холст.** Колонка = глубина зависимости, а не календарь: видно, в каком порядке
  вещи физически могут поехать. Авто-раскладка, ручное закрепление, области, заметки,
  мультивыделение, групповые правки, копирование узлов между проектами.
- **Метрики.** Вес узла = размер транзитивного множества потомков («закрыв это,
  разблокируешь N»), критический путь, слои. Блокирующие и неблокирующие типы связей
  считаются по-разному.
- **Один пул узлов — много представлений.** Страницы: холст, таблица, канбан, дашборд.
  Страница — это фильтр + способ отрисовки, а не отдельный набор данных.
- **Схема настраивается.** Типы узлов, статусы, категории, типы связей, свои поля —
  всё редактируется в интерфейсе, включая инлайн-создание прямо из инспектора.
- **Фасетные фильтры** с числом подходящих узлов у каждого значения.
- **Версии и корзина.** Именованные снимки (до 10 на проект), мягкое удаление проектов,
  валидатор проекта с починкой находок в один клик.
- **Бэкенд** (в работе): аккаунты по приглашению, доски на сервере, ссылки-доступы.
  API на `/api/`, SQLite в именованном docker-томе, миграции применяет сам контейнер
  при старте, ежедневные резервные копии.
- **Экспорт.** JSON, CSV, Markdown, PNG/SVG холста и самодостаточный `viewer.html`
  для отправки тому, у кого ничего не установлено.
- **Тёмная тема**, горячие клавиши, работа офлайн.

## Хранение данных

| Режим | PWA | Файлы на диске | Где данные |
|---|---|---|---|
| `https://graph.heeprod.ru` или `localhost` | ✅ | ✅ File System Access | `.json` на диске + IndexedDB как кэш |
| экспортированный `viewer.html` (`file://`) | ❌ | только просмотр | — |

File System Access и установка как приложение требуют secure context (https или
localhost) — по `file://` они выключаются, всё остальное работает.
FSA поддерживают Chrome/Edge; в Safari и Firefox вместо неё обычные скачивание и загрузка файла.

**Папка-хранилище (как в Obsidian).** Можно указать одну папку — все проекты будут
лежать в ней отдельными `.json` и автосохраняться при каждой правке.

## Быстрый старт

**Локально** — двойной клик по `start.command`: поставит зависимости при первом запуске,
поднимет Vite на 8123 и откроет браузер.

Или руками:

```bash
npm install
npm run dev          # разработка, горячая перезагрузка
npm run build        # сборка в dist/ + шаблон просмотрщика
```

**В Docker:**

```bash
docker compose up -d --build
open http://localhost:8081
```

## Разработка

Код живёт в `src/main.js`, стили — в `src/styles.css`, разметка — в `index.html`.
Функции по-прежнему объявлены плоско и глобально; в конце `main.js` стоит мост в `window`,
без которого тесты и отладка из консоли не видели бы ничего, потому что модуль прячет
объявления в свою область. Подробности, инварианты и грабли — в [docs/SPEC.md](docs/SPEC.md).

Три вещи, которые стоят часов отладки, если про них не знать:

- `const`/`let`, на которые ссылается верхнеуровневый код, объявляйте **до** первого
  использования — иначе TDZ-ReferenceError убивает весь скрипт до `boot()`, и приложение
  молча не стартует;
- добавили функцию, которая нужна тестам или консоли, — допишите её в мост в конце
  `src/main.js`, иначе снаружи её просто нет;
- экспорт `viewer.html` работает только в собранной версии: он тянет
  `viewer-template.html`, который появляется после `npm run build`.

## Проверка

```bash
docker compose up -d --build
node test/smoke.js
```

Гоняет приложение в headless Chrome: загрузка, все типы страниц, перетаскивание
узла мышью, сохранение в IndexedDB и round-trip экспорт → импорт с проверкой,
что позиции узлов и камера не теряются. Подробности — в [test/README.md](test/README.md).

## Деплой

Схема: host-nginx держит TLS и проксирует на контейнер, который отдаёт статику
на `127.0.0.1:8081`. Пошагово — в [deploy/README.md](deploy/README.md).

Деплой автоматический: пуш в `main` → GitHub Actions собирает образ, гоняет
регрессионный прогон, выкатывает на сервер и повторяет прогон по боевому адресу.
Руками, если нужно:

```bash
cd /opt/graph-studio && ./deploy/deploy.sh
```
